# 우리집 AI (family-hub-with-ai)

가족을 위한 **로컬 우선(local-first)** AI 앱. 안내문 사진·글·링크를 넣으면 **일정 / 준비물 / 장보기 / 할 일**로 정리하고, 집 안의 맥을 통해 가족 기기끼리 동기화합니다.

**사진과 글은 집 밖으로 나가지 않습니다.** OCR은 macOS Apple Vision, 정리는 Ollama 로컬 모델이 맥에서 처리합니다. 클라우드 AI나 클라우드 동기화는 쓰지 않습니다.

---

## 현재 구현된 기능

### 입력
- **사진으로 추가**: 카메라 촬영 또는 앨범에서 여러 장 선택 (장수 제한 없음)
- **일정 추가**: 글 붙여넣기 · 공유 링크 · 외부 AI 결과 붙여넣기 · 직접 입력
- 제미나이 공유 링크(`https://share.gemini.google/...`)처럼 이미 정리된 글도 가져와 구조화
- 사진 비율은 항상 원본 유지, 크기·화질만 설정값 적용 (프리셋 50/75/100% 또는 상세 슬라이더)

### 정리
- Apple Vision OCR → 로컬 LLM → 일정/목록 JSON
- 표(시간표)의 열을 유지하고, 반별로 날짜가 다르면 일정을 각각 생성
- 준비물·복장은 준비물 목록으로, 제출/납부 기한은 할 일로
- OCR 신뢰도가 낮으면 검토 화면에 경고 + 링크/직접 입력 안내

### 검토 · 저장
- 검토 화면에서 제목·날짜·시간·장소·수량 수정, 항목 선택/해제
- 각 항목마다 **저장 위치를 일정 또는 할 일(목록)로 선택**
- 링크로 가져온 경우 출처(제목·주소) 표시
- 저장 후 가족 기기와 자동 동기화

### 사진 보관
- 기본은 **분석 후 삭제** (프라이버시 우선)
- 보관 기간(즉시/7일/30일/계속)과 위치(이 기기 / 맥 허브) 선택
- **보관한 사진 보기**: 이 기기 사진과 맥 허브 사진을 모아 보고, 크게 보기·삭제
- 저장 위치와 실제 사용량(장수·용량)을 설정에서 확인

### 기기 · 동기화
- **허용 기기제**: 첫 기기 부팅 코드 → 이후 초대 코드 → 보호자 승인
- 토큰은 SHA-256 해시로만 서버에 저장, 해제는 즉시 반영
- 오프라인 우선: 맥이 꺼져 있어도 폰에서 사용, 연결되면 밀린 변경분 동기화
- 충돌은 `updatedAt` 기준 최신 우선(LWW), 삭제는 tombstone으로 전파
- **언제 맞춰지나**: 저장하면 바로 허브로 올리고, 앱이 화면에 떠 있는 동안 20초마다, 앱으로 돌아올 때, 홈 화면을 열 때 새 변경을 당겨옵니다.
- **다른 폰이 백그라운드일 때**: 그 폰에서 앱을 열어야 최신 내용이 보입니다. 실시간 푸시 채널은 쓰지 않습니다(배터리·프라이버시).
- **거절된 변경**: 허브에 더 최신 행이 있으면 조용히 버리지 않고 커서를 되감아 허브 기준으로 다시 맞춥니다. 허브 로그에 `sync ops rejected` 로 남습니다.
- **서버 주소 변경**: 맥의 IP가 바뀌어도 기기 토큰은 그대로이므로 다시 연결할 필요가 없습니다. 앱이 새 주소를 자동으로 찾아보고, 실패하면 `설정 → 연결 → 서버 주소 변경` 에서 직접 넣을 수 있습니다.

### 보안 · 개인정보
- 사진·글은 같은 Wi-Fi(또는 Tailscale) 안에서만 오갑니다
- 링크 가져오기는 **공개 링크만** 허용, `localhost`·사설 IP·내부망 주소는 차단
- 링크를 읽을 때만 해당 사이트에 접속하며, 가져온 글은 맥 안에서만 처리
- 외부 AI로 사진을 보내는 기능은 사용자가 직접 선택할 때만 동작하며, 그 전에 경고를 표시

## 구성

```
iPhone / Android (Expo Go)
        │  같은 Wi-Fi 또는 Tailscale
        ▼
홈 Mac ── hub (Fastify + SQLite)
          ├─ /v1/sync        변경분 push/pull (오프라인 큐)
          ├─ /v1/extract     사진/글/링크 → 구조화 JSON
          ├─ /v1/photos      보관한 사진 목록·원본
          └─ /v1/devices     기기 승인·해제 (허용 기기만 접근)
```

- **AI 파이프라인**: `Apple Vision OCR → (필요 시 원근 보정) → Ollama`
- **빠른 모드** `gemma4:e4b` (약 6~15초), **정확 모드** `qwen2.5:14b-instruct` (30초 이상)
- `gemma4`는 생각(thinking) 모델이라 추출 시에는 `think:false`로 실행합니다. 켜 두면 출력 한도를 생각에 다 써서 빈 답이 나옵니다.

## 폴더

| 경로 | 설명 |
|---|---|
| `app/` | Expo(React Native) 앱. Expo Go로 iOS·Android 테스트 |
| `hub/` | 맥에서 도는 서버. 동기화 + AI 파이프라인 |
| `ocr/` | Apple Vision OCR CLI (Swift, 온디바이스) |
| `docs/` | 보안·운영 문서 |

### 데이터가 저장되는 곳

가족 데이터는 **휴대폰과 맥 두 곳**에 나뉘어 저장됩니다. 클라우드는 쓰지 않습니다.

| 위치 | 무엇이 | 경로 |
|---|---|---|
| 휴대폰 | 일정·목록·기기 정보 | 앱 전용 저장소의 `family-hub.db` (expo-sqlite) |
| 휴대폰 | 보관한 사진 | 앱 전용 저장소의 `photos/` |
| 맥 | 원본 DB | `hub/data/hub.db` |
| 맥 | 보관한 사진 | `hub/data/photos/` |
| 맥 | 분석 중 임시 파일 | `hub/data/tmp/` (처리 후 삭제) |

앱 안에서는 **설정 → 저장 위치**에서 사진 장수·용량을 확인하고 **보관한 사진 보기**로 이동할 수 있습니다.
`hub/data/` 는 `.gitignore` 에 있어 Git에 올라가지 않습니다.

## 준비물

- macOS (Apple Silicon 권장), Node 22+ (개발 환경은 26), Ollama
- 폰: Expo Go 앱 (App Store / Play Store)
- 링크 가져오기를 쓸 경우: 맥에 Chrome (없으면 `CHROME_BIN`으로 경로 지정)
- (선택) Tailscale — 집 밖에서 접속할 때

```bash
# 로컬 모델 (이미 있으면 생략)
ollama pull gemma4:e4b            # 빠른 모드 (기본)
ollama pull qwen2.5:14b-instruct  # 정확 모드
```

## 처음 실행

```bash
# 1) OCR CLI 빌드
cd ocr && ./build.sh && cd ..

# 2) 허브 의존성 + 가족 생성 + 첫 기기 코드
cd hub
npm install
npm run init -- --family "우리 가족"
```

`npm run init` 이 아래를 출력합니다.

```
첫 기기 연결 코드: EKTQBP3D   (24시간 유효)
http://192.168.0.10:4317
```

```bash
# 3) 허브 실행 (맥이 켜져 있는 동안)
npm start
```

처음 실행하면 macOS가 "들어오는 연결을 허용할까요?"라고 물을 수 있습니다. **허용**을 선택해야 폰에서 접속됩니다.

```bash
# 4) 앱 실행
cd ../app
npx expo start
```

폰의 Expo Go로 QR을 찍고, 앱에서 **서버 주소 + 연결 코드**를 입력합니다. 서버 주소는 Metro 주소에서 자동으로 채워지고, 필요하면 **주소 자동 입력** 버튼을 쓰면 됩니다.

> 첫 기기는 **부모 기기**로 등록됩니다. 이후 기기는 `설정 → 기기 관리 → 초대 코드 만들기` 로 코드를 발급하고, 새 기기에서 입력한 뒤 **보호자 기기에서 승인**해야 합니다.

> 공유기에서 맥의 IP를 **고정(DHCP 예약)** 해 두면 주소가 바뀌지 않습니다. 바뀌었다면 앱의 `설정 → 연결 → 서버 주소 변경` 에서 새 주소만 넣으면 되고, 연결 코드는 다시 필요 없습니다.

## 사용법

### 사진으로 정리하기

1. 홈 → **사진으로 추가** → 촬영/앨범 선택
2. (선택) 메모에 “다음 주 금요일 현장학습” 같은 힌트 입력
3. **AI에게 정리 맡기기** → 6~15초 대기
4. 검토 화면에서 확인·수정 → **저장**

### 글·링크로 정리하기

홈 → **일정 추가** 에서 세 가지 방법을 씁니다.

1. **글 붙여넣기**: 문자·카톡·공지문을 그대로
2. **링크 가져오기**: 제미나이 공유 링크, 학교/기관 안내 페이지, 블로그 주소
   - 자바스크립트로 그려지는 페이지는 맥의 Chrome을 잠깐 실행해 읽습니다
   - 공개 링크만 가능하고, 로그인이 필요한 주소·내부 IP는 차단됩니다
3. **외부 AI 결과 붙여넣기**: 프롬프트를 복사해 외부 AI에 사진과 함께 보내고, 받은 결과를 붙여넣기
   - 이때만 사진이 가족 허브 밖으로 나갑니다

### 검토 화면

- 항목별 **저장 위치**에서 `일정` / `할 일(목록)` 을 고를 수 있습니다
- 일정으로 넣으려면 날짜가 필요하고, 할 일은 날짜 없이도 저장됩니다
- **일정-준비물/할 일 연결**: 추출된 준비물·할 일을 함께 추출된 일정(또는 기존 일정)과 바로 연결하거나 해제할 수 있습니다
- **구글 캘린더 연동**:
  - `🔍 구글 캘린더에 추가`: 클라우드 설정 없이도 브라우저를 열어 구글 캘린더에 수동으로 저장합니다 (앱 저장과는 별도로 동작하는 수동 추가 기능입니다)
  - `허브 자동 동기화`: 맥 허브 키체인에 서비스 계정이 등록된 경우 전용 구글 캘린더(`우리집 AI`)와 양방향 동기화합니다
- 링크로 가져온 경우 상단에 출처가 표시됩니다
- **원본 글자 보기**로 OCR이 읽은 텍스트를 확인할 수 있습니다

### 보관한 사진

`설정 → 보관한 사진 보기` 또는 `사진 설정 → 보관한 사진 보기`

- **이 기기**: 앱 전용 저장소에 보관된 사진
- **맥 허브**: 맥에 보관된 사진 (가족 기기에서도 표시)
- 사진을 누르면 크게 볼 수 있고, 이 기기 사진은 삭제할 수 있습니다
- 사진을 보관하지 않는 설정이면 목록이 비어 있고, 설정으로 안내합니다

## 사진 품질 · 보관 정책

- 기본: **분석 후 삭제** (원본을 남기지 않음)
- 보관 기간: 즉시 삭제 / 7일 / 30일 / 계속
- 보관 위치: 이 기기 / 맥 허브
- 품질: 50% · 75% · 100% 프리셋 또는 최대 크기(px)·JPEG 품질 슬라이더
- **비율은 항상 원본 그대로**이고, 크기와 화질만 바뀝니다
- 사진 장수 제한은 없습니다

사진이 흐리거나 작아 OCR 신뢰도가 낮으면 검토 화면 위에 경고가 뜹니다. 이때 **일정 추가 → 링크 가져오기**를 쓰면 이미 정리된 글을 그대로 구조화할 수 있습니다.

## 구글 캘린더 연동 (선택)

두 가지 방식을 함께 지원합니다.

1. **수동 추가 (A안 · 설정 불필요)**
   - 검토 화면(`review`)과 일정 상세 모달(`schedule`)에서 **`🔍 구글 캘린더에 추가`** 를 누르면 브라우저에서 구글 캘린더 일정 등록 창이 열립니다.
   - 주의: 브라우저에서 직접 저장하는 **수동 사본**이므로 앱 내부 일정과 자동 동기화되지는 않습니다.

2. **허브 주도 양방향 동기화 (C안 · macOS 키체인 기반)**
   - Google Cloud에서 Calendar API를 활성화하고 서비스 계정(Service Account) JSON 키를 발급합니다.
   - 구글 캘린더에서 **`우리집 AI`** 전용 캘린더를 새로 만들고, 서비스 계정 이메일에 **`일정 변경 권한(Make changes to events)`** 으로 공유합니다.
   - 맥에서 아래 명령으로 키체인에 등록합니다 (원본 JSON 파일은 등록 후 안전하게 백업·삭제):

```bash
cd hub
npm run google:setup -- --key /path/to/service-account.json --calendar <캘린더ID>
npm run google:setup -- --status   # 연결 상태 확인
npm run google:setup -- --clear    # 키체인에서 제거
```

### 구글 연동 보안 · 안전 정책
- **키체인 전용 보관**: 서비스 계정 개인키는 **macOS 키체인(`family-hub-google`)** 에만 저장되며, 휴대폰·Git·앱 번들에는 절대 포함되지 않습니다.
- **동기화 범위**: `일정(events)`만 동기화하며 준비물·할 일·장보기 목록은 집 안(로컬/허브)에만 유지됩니다.
- **반복 일정 보호**: 구글 캘린더의 반복 일정은 180일치 단일 일정(`G · 반복`)으로 펼쳐서 보여주며, 앱에서는 **읽기 전용(READ-ONLY)** 으로 보호됩니다 (준비물·할 일 연결은 가능).
- **사본 보존 원칙**: 일정 상세에서 `구글 캘린더 동기화` 스위치를 꺼도 **구글 캘린더에 이미 올라간 사본은 삭제하지 않습니다.**
- **충돌 감지 (`If-Match` / `ETag`)**: 동시에 수정된 경우 `updatedAt` 타임스탬프 기준으로 최신 수정본을 반영하고 일정에 충돌 해결 안내(`⚠ 구글 수정됨`)를 표시합니다.

## 집 밖에서 접속 (선택)

1. 맥과 폰에 Tailscale 설치, 같은 계정으로 로그인
2. 맥에서 HTTPS 활성화 후 프록시:

```bash
tailscale serve --bg 4317
tailscale ip -4          # 100.x.y.z 주소를 앱 서버 주소로 사용
```

3. 앱 **설정 → 연결 → 서버 주소 변경** 에서 `http://100.x.y.z:4317` 로 변경 (또는 serve 주소)

자세한 보안 설정은 [docs/SECURITY.md](docs/SECURITY.md) 참고.

## 상시 실행 (launchd)

```bash
cd hub
./scripts/install-service.sh     # 로그인 시 자동 시작 + 죽으면 재시작
./scripts/uninstall-service.sh   # 해제
tail -f data/hub.log
```

맥이 잠자기로 들어가면 접속이 끊깁니다. 전원 연결 + `시스템 설정 → 잠자기 방지` 또는 `caffeinate -s` 를 권장합니다.

| `EADDRINUSE 0.0.0.0:4317` | 이미 허브가 실행 중입니다. `lsof -ti tcp:4317` 로 확인 후 기존 프로세스를 쓰거나 종료하세요 |
| iPhone Expo Go: `You need to be signed in to Expo Go and Expo CLI` | Expo Go iOS는 실제 기기에서 개발 서버를 열 때 **CLI와 기기가 같은 Expo 계정**으로 로그인되어 있어야 합니다. 맥에서 `npx expo login`, iPhone Expo Go 오른쪽 위 계정 아이콘에서 같은 계정으로 로그인 후 **Try again**. Android·iOS 시뮬레이터는 로그인 없이 동작합니다 |
| 다른 폰에 방금 넣은 일정이 안 보임 | 그 폰에서 앱을 열면 즉시 당겨옵니다. 홈 상단 배지가 `최신`인지, `대기 n건`으로 남아 있지 않은지 확인하세요 |
| 앱이 서버를 못 찾음 | 맥과 폰이 같은 Wi-Fi인지, `npm start` 중인지, 주소의 IP가 맞는지 |
| 맥 IP가 바뀜 (Wi-Fi 재접속·공유기 재부팅) | 개발 중에는 앱이 Metro가 알려준 현재 주소로 **자동 복구**를 시도합니다. 그래도 안 되면 앱 **설정 → 연결 → 서버 주소 변경**에서 새 주소로 바꾸세요. 연결 코드는 다시 필요 없습니다. `npm start` 로그에 현재 주소가 표시됩니다 |
| 서버 주소를 바꿔도 계속 오프라인 | 홈 경고의 **서버 주소 변경** 링크로 바로 열 수 있습니다. 그래도 안 되면 허브가 켜져 있는지, 방화벽이 4317을 막지 않는지 확인하세요 |
| `보호자 승인 대기` | 보호자 기기 → 기기 관리 → 승인 |
| AI가 느림 | 정확 모드(14B)는 30초 이상 걸립니다. 빠른 모드로 전환 |
| AI가 빈 결과를 줌 | 허브를 최신 코드로 재시작했는지 확인 (`think:false` 수정 포함) |
| 모델 없음 | `ollama pull gemma4:e4b` |
| OCR 실패 | `cd ocr && ./build.sh` 로 바이너리 재빌드 |
| 사진이 안 읽힘 | 검토 화면 경고 확인 → `일정 추가`에서 글·링크로 정리 |
| 링크를 못 읽음 | 공개 링크인지, 맥에 Chrome이 있는지 확인 (`CHROME_BIN`) |
| 보관한 사진이 비어 있음 | 사진 보관이 ‘분석 후 삭제’인지 확인. 보관 기간을 켜야 저장됩니다 |
| 앱이 시작하자마자 빨간 화면 | Expo Go에 없는 네이티브 모듈 문제. 최신 코드로 다시 실행 |
| 일정 알림이 안 옴 | Expo Go에는 필요한 네이티브 모듈이 없어 알림을 꺼두었습니다. 앱은 정상 사용 가능 (`app/src/lib/notify.ts` 주석 참고) |

## 알려진 한계

- 사진 OCR 정확도는 실제 폰 사진(기울기·조명)에서 계속 측정 중입니다. 현재는 원근 보정과 줄 병합까지 적용되어 있습니다.
- 링크 가져오기는 맥에 Chrome이 필요합니다 (Safari는 헤드리스 덤프 미지원).
- 맥 허브 사진은 허브가 켜져 있을 때만 볼 수 있습니다.
- Expo Go에서는 알림이 동작하지 않습니다. 개발 빌드(`npx expo run:android`)에서 다시 켤 수 있습니다.
- iOS 네이티브 빌드, 워치 앱, AI 튜터는 아직 시작 전입니다.
